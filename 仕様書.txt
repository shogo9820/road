# 🍻 宅飲み人生ゲーム 究極詳細開発仕様書
サークル生活の思い出とアルコール

## 1. 建築アーキテクチャ・通信フロー全体像
本システムは、Node.js (Express) + Socket.io をバックエンドとし、フロントエンドを「PC大画面（親機）」と「スマートフォン（子機：コントローラー）」に完全に分離した、リアルタイム同期型すごろくアーキテクチャです。

### 1.1 状態管理
* Single Source of Truth: 全プレイヤーのステータス、位置、マップデータの変更、ルーレットの出目は、サーバー側（server.js の rooms オブジェクト）が100%一元管理します。
* 差分同期: クライアント側でアクションが発生すると、サーバーで内部状態が更新され、syncGameState イベントによってRoom内の全端末へ最新のプレイヤー配列が一斉配信されます。

### 1.2 主要通信イベント一覧
* createRoom: スマホからホスト名を受け取りルーム(4桁コード)を作成。
* joinRoom: スマホからコードを受け取りルームに参加。
* startGame: スマホからゲーム開始指示を受け取り、正式なステータス(createPlayer雛形)を一括生成してPC・スマホにゲーム画面を強制展開。
* requestSpinRoulette: スマホからの回転要求。サーバーが1〜10の出目をランダムに決定し、spinRouletteで一斉に3秒間回す合図を配信。
* previewRouteSelection / confirmRouteSelection: 分岐点での仮進路描画および進路確定処理。
* triggerJobChoice / showJobChoice: 役職マス着地時の就職モーダル中継。
* triggerCoupleEvent / showCoupleEvent: 41番マス着地時にスマホをピンクのカップルモードに変身させる。
* coupleRouletteResult / startCoupleSecondRoulette: 1回目の偶数判定と、成功時の他プレイヤーランダム配置対応表の配信。
* coupleSecondRouletteResult / coupleEventFinished: 2回目告白スピンの合否判定と恋人フラグ・飲酒杯数の加算処理。
* showGraduateEvent / graduateRouletteResult / closeGraduateModal: 89番マスでの卒業判定モーダルの強制展開と出目(6以上合格/5以下留年)に応じた運命分岐。
* debugWarp / executeDebugWarp: 開発用ワープ機構。

## 2. データベース・オブジェクト構造
### 2.1 プレイヤーオブジェクト雛形
* id: 固有識別ID
* name: プレイヤー名
* jobId / job: 役職IDおよび役職名（初期値は"mob" / "モブ"、最大HP容量等に影響）
* baseCap: 基礎肝臓HP容量 (初期値: 80)
* bonusCap: 追加肝臓HP容量 (初期値: 0)
* currentHp: 現在の肝臓HP値 (初期値: 80)
* drinkCount: 累計飲酒杯数 (初期値: 0)
* happiness: 幸福度ポイント (初期値: 100)
* position: 現在位置マスID (0〜99)
* location: 現在の滞在場所名
* 各種フラグ: isLover (恋人フラグ), skipTurn (休みフラグ), hasJob (就職フラグ), isRepeat (留年フラグ), graduateChecked (卒業判定済みフラグ)

## 3. クライアント表示・Canvas制御
### 3.1 盤面描画アルゴリズム (board.js)
* Canvas基本仕様: セルサイズ 15px、解像度 横900px・縦840px。
* 留年ルート動的非表示: 描画マスIDが 90〜98 の場合、現在手番プレイヤーが p.isRepeat !== true であれば return で描画をスキップし、完全に画面から隠蔽します。
* 分岐影マスク: 0番、49番の分岐マスで進路選択中、選ばれなかった方のルートの上に rgba(0, 0, 0, 0.65) の黒い四角形を重ね描きして暗転させます。
* ピン衝突回避アルゴリズム: 同一マスに複数プレイヤーが重なる場合、2人目以降を 2*pi/4 づつ回転させた円周上(半径10px)にオフセット計算して分散描画します。

## 4. ゲームエンジンのコア・ロジック
### 4.1 自動移動探索
* スマホの回転停止3秒後、PC側で 250ms 間隔の setInterval タイマーが起動。nextId 配列をトレースしながら1マスずつ滑らかに進みます。途中で force_stop 等の強制ストップマスを踏んだ場合は、出目が残っていても緊急着地します。
### 4.2 急性アルコール中毒計算
* 飲酒ペナルティのあるマスに止まると、currentHp が減少。currentHp <= 0 に到達した瞬間、幸福度 -30pt、次ターン1回休み(skipTurn = true)を設定し、肝臓HPを最大値まで一気に全回復(蘇生)させます。

## 5. 特殊イベントマス完全制御
### 5.1 進路の1本道化
* 分岐マス（0番、49番）で進路が選ばれると、サーバー側で MAP_SQUARES の該当マスの nextId 配列を、選択した進路先頭の「単一の数値」へと上書き(破壊的変更)し、通常の syncGameState で同期します。
### 5.2 カップル成立イベント
* 1回目で偶数を出した後、サーバー側で自分以外の全プレイヤーを出目1〜10へフィッシャー・イェーツ・シャッフルでランダムマッピング。2回目で他プレイヤーのいるマスを引き当てればカップル成立（isLover = true、両者杯数 +1）。誰もいないマスは告白失敗。
### 5.3 運命の卒業判定・隠し留年ルート
* プレイヤーが89番マスにいるターン開始時、150msのバッファを経て独立信号 showGraduateEvent をPCへ直撃送信し、モーダルを展開。
* 出目 6以上（合格）: 内部位置を直接 99 (GOAL) に書き換え、syncGameState でピンを瞬間ワープ。到着イベント(case 99)を正常キックし、スマホには showGraduateNextButton で交代ボタンのみを出現させます。
* 出目 5以下（留年）: 89番の nextId を 90 へ上書き、p.isRepeat = true を刻みます。同期により PC Canvas 上に隠されていた留年ルート（90〜98番マス）が動的に線路のように開通し、スマホの通常移動ルーレットが復活します。

## 6. 完全統合デバッグシステム
* スマホ最下部のデバッグゾーンにマスID（41や89など）を入力してワープを叩くと、debugWarp が送信され、サーバー経由で全員を瞬間移動。PC側は着地したマスの特性を自動解析し、対応する役職選択やイベントモーダルをその場で即座に自動起動させ、ノータイムで検証が可能です。
